# ADR-0003：分組報酬與 IC 採非重疊的換倉日網格

- 狀態：已接受
- 日期：2026-08-13
- 相關：ADR-0001（跨停牌報酬照實計算）、ADR-0002（可交易性判在成交日）

## 脈絡

`deep_eval.py` 原本每個交易日都算一列統計。持有期 n > 1 時，這些列彼此重疊：
1/02 那筆握的是 1/03～1/09 的部位，1/03 那筆握的是 1/04～1/10 的部位，中間有 n−1
天握著幾乎相同的股票。**它們不是 n 次獨立的交易。**

把重疊的列當成獨立樣本加總、年化，隱含的假設是同時開了 n 個平行帳戶輪流進場。
實際上只有一個帳戶。這讓幾件事失真：

- `annual_return`、`max_drawdown`、`monthly_win_rate` 不對應任何一個真實帳戶走過的路徑
- 日 IC 高度自相關，未修正的 t 被系統性放大
- 換手率是「每 n 天換一次」的策略，但報酬序列是「每天換一次」的網格，兩者口徑不一致

導火線是要加交易成本。成本必須逐次換倉扣，而「一次換倉」在重疊的網格上沒有定義。

參考實作 panda_factor 是非重疊的：`factor.py:286` 的 `if day_count % self.period != 0:
continue` 每 period 天才取一列，IC 與分組報酬共用同一個迴圈。這個分歧先前沒有記錄
在任何地方，而且在 hp=1 時完全看不出來（每天都是週期起點），因此一直沒被發現。

## 決策

**評估層只在換倉日上計算。** 換倉日定義為面板交易日曆上每 `holding_period` 個交易日
取一天，從第一個交易日起算。分組報酬、多空價差、逐日 IC、IC 衰減**全部**套用同一個
網格。

四個附帶決定：

1. **網格定義在面板的交易日曆上，不是因子自己的日期上。** 同一份面板下所有因子共用
   同一組換倉日，彼此可比；因子的覆蓋範圍不影響網格。
2. **網格固定，不因資料品質重排。** 某個換倉日若因相異值不足以支撐分組數而被整天
   丟棄（`dropped_days`），那一次換倉在序列中缺席，下一次仍落在原本的位置。不順延
   到隔天、不從隔天重新起算。panda_factor 在這裡有個 bug：跳過無效日時沒有遞增
   `day_count`（`factor.py:280-287`），網格會偷偷偏移，同一個因子換一份稍有差異的
   面板就得到不同的抽樣日。
3. **換手率比較的對象是上一個換倉日的名冊。** 序號打在換倉日網格上而不是名冊自己的
   日期上，因此網格上的洞會讓那一次換倉自然對不到上一期而被排除，不會把隔了兩期的
   兩張名冊誤當成相鄰。
4. **`newey_west_lags` 預設改為 0。** 非重疊的序列沒有重疊造成的自相關。`nw_t`/`nw_p`
   欄位保留不刪，明確指定 lag 仍然有效。

`_performance` 的年化係數不變，仍是 `TRADING_DAYS / holding_period`——每年的換倉次數
沒變，變的是不再重複計算同一段持有區間。

## 後果

**hp=1 不受任何影響。** period=1 時每個交易日都是換倉日，網格是恆等的。這是最強的
護欄，`test_holding_period_one_results_are_pinned` 把改動前的數字釘死；
`test_holding_period_one_evaluates_every_trading_day` 斷言沒有任何一天被抽掉。

**hp > 1 的所有既有數字都會變。** 這是刻意的——舊數字建立在錯誤的假設上。與 hp>1 的
歷史報表對不上是預期行為，不是 bug。

**樣本數少 n 倍。** hp=5 時 725 列變 145 列，hp=20 時只剩 36 列。這是這個決策付出的
代價，而且是真的代價：36 個點算出來的夏普與最大回撤幾乎沒有統計意義。**持有期越長，
這些指標越該當成粗略的量級而不是估計值。** 專案目前只做短持有期，因此接受。

**起點會影響結果。** 取第 0、5、10 天與取第 2、7、12 天是兩組不同的數字。非重疊本來
就有這個性質，不做多起點平均——那等於把重疊偷偷加回來。判讀時要知道這件事。

## 被否決的選項

**維持重疊、靠 Newey-West 修正。** 樣本效率高很多，而 `nw_lags` 本來就是為此而設。
否決的理由是 HAC 只修正統計檢定的標準誤，它修不了 `annual_return` 與 `max_drawdown`
——那兩個指標在重疊網格上根本不對應任何真實帳戶，而這個模組的整個重點是「真實可
執行的淨績效」。

**只有分組報酬非重疊、IC 維持全樣本。** IC 是診斷指標，樣本越多越準，而且它不宣稱
可交易。否決的理由是專案只做短持有期，hp=5 仍有 145 個觀測值，足以支撐 t 檢定；為了
多一點樣本而讓 `group_stats` 與 `metrics` 跑在兩個不同的日期網格上，判讀成本高於收益。
若日後真的要做長持有期，這個選項值得重新評估。
