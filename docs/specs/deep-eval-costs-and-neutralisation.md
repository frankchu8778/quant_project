# 深度回測下一階段：交易成本與中性化

兩個獨立但會互相影響的功能，接在 `src/factor/components/` 既有的深度回測之上。
既有設計與術語見 `src/factor/components/usage.md` 與 `docs/adr/`。

**貫穿兩者的原則**（沿用既有模組的做法）：新指標一律**並列**輸出而不取代舊的。
看不到 gross 就不知道成本吃掉多少；看不到原始因子就不知道中性化拿走了什麼。

---

## 功能一：手續費與滑點

### 現況

`group_stats` 的所有報酬都是 **gross**。`turnover` 已經算出來了，但只回傳各組的
**平均值**（`DeepFactorTester._turnover`），成本計算需要的是逐日序列。

### 設計決定

1. **成本打在逐日報酬上，不是從年化報酬扣一次。**
   夏普、最大回撤、月度勝率都必須用扣後序列重算——先年化再扣會讓這三個指標維持
   gross 的形狀，只有報酬那一欄變小，是錯的。
   → `_turnover` 要改成回傳逐日 turnover，平均值變成它的下游。

2. **台股的成本結構不對稱，不能用單一 round-trip 費率。**
   - 手續費 0.1425%，**買賣都收**（實務上有折扣，要能設）
   - 證券交易稅 0.3%，**只有賣出收**
   - 滑點另計，以 bps 表示，買賣都吃
   → config 至少要 `fee_rate`、`tax_rate`、`slippage_bps` 三個獨立參數，
     預設值要在 docstring 裡寫清楚出處。

3. **買進與賣出的換手率要分開算。** 這是最容易做錯的地方。
   現有的 turnover = 本期在組內、上期不在的檔數 ÷ 上期檔數，衡量的是**新進場**比例。
   賣出比例是「上期在、本期不在」÷ 上期檔數。等權組合下，只有當組內檔數不變時
   兩者才相等；檔數變動（宇宙進出、可交易性剔除）時不等。
   → 分別算 `buy_turnover` / `sell_turnover`，買進成本套前者、賣出成本（含證交稅）
     套後者。

4. **多空組合的成本是兩腿相加，不是平均。**
   `group_stats` 現在的多空 turnover 取兩端平均，那是為了對齊 panda_factor 的顯示口徑。
   成本不能沿用這個數字——實際上兩條腿都要各自付費。

5. **不要動既有欄位的定義。** 新增 `net_annual_return`、`net_sharpe`、`net_max_drawdown`、
   `net_monthly_win_rate`、`cost_annual`（成本本身的年化，方便一眼看出侵蝕多少）。

### 驗收

- 費率全設 0 時，net 指標與 gross **完全相等**（不是近似）。
- turnover 為 0 的因子（跨日固定值）成本為 0。
- 每日整批對調的因子，成本 ≈ 每日 (買進費率 + 賣出費率 + 稅 + 2×滑點)。
- 已知 turnover 與費率下，手算一天的成本與程式一致。

## 功能二：市值中性化 / 行業中性化

### 資料

已經備妥，不需要新的上游工作：`market_value_million`、`industry`、`subindustry`
都在 DuckDB 的 `daily_data`，而 `align_and_adjust` 是 `SELECT *`，所以
`DeepBacktestConfig(extra_cols=("market_value_million", "industry"))` 就能帶進面板。

### 設計決定

1. **做法**：逐日截面回歸 `factor ~ log(市值) + 產業 dummies`，取**殘差**當中性化後的因子。

2. **用 log 市值，不是原始市值。** 市值分布極度右偏，直接回歸會被少數大型股主導，
   殘差裡仍然留著市值效應。

3. **順序：剔除 → winsorize → 中性化 → 分組。**
   - 中性化必須在**剔除不可交易之後**——這是 ADR-0002 的同一個理由：殘差取決於截面
     組成，把買不到的股票放進回歸會污染所有人的殘差。
   - 中性化在 **winsorize 之後**——極端值會主導回歸係數，先截斷再回歸比較穩。
   - 這個順序要寫成測試，不能只寫在註解裡。

4. **秩虧與極小產業**。某天某產業只有一檔股票時，該產業的 dummy 會完全解釋那一檔，
   殘差恰為 0——那不是「中性化後沒有訊號」，是自由度用完了。需要一個每產業最小檔數
   門檻，未達門檻的併入「其他」或整批剔除，並且**要計數回報**（比照 `dropped_days`）。

5. **產業缺值不要默默歸成一類。** 缺值與「確實屬於某個小產業」是兩件事。決定要明確
   （建議獨立成 `unknown` 並計數），不要讓它悄悄影響回歸。

6. **輸出並列。** 同一個因子跑 raw 與 neutralised 兩份結果對照，才看得出中性化拿走了
   什麼。若原始因子的 IC 幾乎全部來自市值曝險，中性化後會塌掉——那正是要知道的事。

### 驗收

- 中性化後的因子與 log 市值的截面相關係數 ≈ 0。
- 對每個產業，中性化後因子的組內平均 ≈ 0。
- 因子本身就是 log 市值時，中性化後殘差 ≈ 0，IC 也 ≈ 0。
- 與市值/產業完全無關的因子，中性化前後的 Rank IC 幾乎不變。
- 產業只有一檔的日子有被計數，不是靜悄悄產生 0 殘差。

## 兩者的交互作用

中性化會改變分組成員，因此**會改變 turnover，也就改變成本**。兩個功能要能組合使用，
且成本必須算在中性化**之後**的組合上。四種組合（raw/neutralised × gross/net）都要能跑。

## 不做的事

- 不加 benchmark 衍生指標（超額報酬、跟蹤誤差、資訊比率）。理由同既有模組：
  上游的 benchmark 是宇宙內等權平均而非市場指數。
- 不改 `src/factor/single_factor_eval.py`（快篩刻意保持粗糙）。
- 不 import `panda_factor`。
